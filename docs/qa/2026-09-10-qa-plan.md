# QA plan for the changes of 2026-09-10

This document lists what to test by hand, and what the app must answer. It
covers every commit from `cfcb73d` to `ce54b50`.

The day added three large things: the trip accounts (the money page, the
balances and the currency), the organiser column beside the trip pages, and the
invite link that opens with no account. It also moved the trip settings out of
the app settings and changed the navigation bar.

A term used below: *money line* means one row of the trip accounts. A line is an
expense, an income, or a transfer between two guests.

## How to prepare a test trip

1. Open the app and create a trip that runs from today to today plus 4 days.
2. Add 3 guests: Alice, Bob, and Cara. Give Cara a headcount of 2.
3. Add 2 rooms with 3 beds in total.
4. Give Alice a stay of 4 nights, Bob 2 nights, and Cara 4 nights.
5. Open `/trips/<id>/money`.

Unless a story asks for another trip, use this trip for every money story below.

## 1. The money page

### Story 1.1: Add the first line

As an organiser, I add what the group paid, so the app can say who owes whom.

| Step | Input | Expected output |
|---|---|---|
| Open the money page with no line | none | The page shows "Nothing spent yet" and a button "New line". |
| Click "New line", type title `Shopping`, amount `90`, payer `Alice` | Split "Equally", everybody picked | The dialog closes. A toast says "Line added". |
| Read the list | none | One card: "Shopping", "Alice paid, for 3 guests", `€90.00`, and today's date. |

Make sure that the amount field accepts `90,50` with a comma. The form reads a
comma as a decimal point.

### Story 1.2: See who owes whom

| Step | Input | Expected output |
|---|---|---|
| Click "Settle up" | none | A table with one row per guest: Paid, Owes, Balance. |
| Read Alice's row | 90 paid, one third owed | Paid `€90.00`, Owes `€30.00`, Balance `€60.00` in green. |
| Read Bob's row | none | Balance `-€30.00` in amber. |
| Read "Payments to make" | none | Two lines: Bob pays Alice `€30.00`, Cara pays Alice `€30.00`. |

The list of payments never holds more payments than there are guests, minus one.

### Story 1.3: Record a payment in one tap

| Step | Input | Expected output |
|---|---|---|
| Click "Record it" on "Bob pays Alice" | none | A toast says "Payment recorded". |
| Go back to "Expenses" | none | A new line "Bob pays Alice back" of `€30.00`. |
| Go back to "Settle up" | none | Bob's balance is `€0.00`. Only Cara still owes. |

### Story 1.4: The split rules

Test each rule with a bill of `100` and three guests picked.

| Rule | Input | Expected output |
|---|---|---|
| Equally | none | The preview reads `€33.34`, `€33.33`, `€33.33`. The three add up to `€100.00`. |
| By parts | Alice 1, Bob 5, Cara 3 | The preview reads `€11.11`, `€55.56`, `€33.33`. |
| By nights | Alice 4, Bob 2, Cara 4 nights with headcount 2 | Cara pays for 8 person nights, so she pays the most. |
| By amount | 30 / 30 / 30 | A red line says "The amounts come to €90.00 of €100.00". Save is refused. |
| By amount | 40 / 30 / 30 | The line turns grey and the save works. |

Every rule must always divide the whole amount. Add the preview figures and
compare them to the amount, on each rule.

### Story 1.5: The three kinds of line

| Kind | What to do | Expected output |
|---|---|---|
| Expense | Alice pays 60 for everybody | Alice's balance goes up by what the others owe. |
| Money in | Alice receives a 30 deposit back for everybody | Alice's balance goes down. The card shows `+€30.00` in green. |
| Payment between guests | Bob pays Alice 20 | The split rules disappear. The form asks "From" and "To". |

Pick the same guest in "From" and in "To". The form must refuse the line and
say "Pick a guest other than the payer".

### Story 1.6: Edit and delete a line

| Step | Input | Expected output |
|---|---|---|
| Click a card | none | The dialog opens with every field filled from the line. |
| Change the amount to `120` and save | none | The card and the balances both show the new figure. |
| Open the line, change a field, press Escape | none | A dialog asks to discard the change. |
| Open the line and click "Delete this line" | Confirm | The card disappears. The balances drop that line. |

### Story 1.7: What the form refuses

| Input | Expected message |
|---|---|
| Empty title | "Required" under the title. |
| Amount `0` or empty | "Type an amount above zero". |
| Amount `2000000` | "The amount must be 1000000 or less". |
| No guest picked | "Pick at least one guest this line is for". |
| Split by nights, and no picked guest slept a night | "None of these guests slept a night on this trip". |

### Story 1.8: The page keeps its view

| Step | Expected output |
|---|---|
| Click "Settle up", then reload the page | The page opens on "Settle up". The address holds `?view=balances`. |
| Open `/trips/<id>/money?view=nonsense` | The page opens on "Expenses" and does not fail. |
| Press the browser back button | The earlier view comes back. |

### Story 1.9: The easter egg

Tap the page title "Money" ten times. Money emoji fall down the screen. Turn
"reduce motion" on in the operating system and repeat. Nothing falls.

## 3. Money on the other pages

### Story 3.1: The organiser column

Open a trip page on a window wider than 1280 pixels. The right column shows
four cards, and the last is "Where the money stands".

| State | Expected output |
|---|---|
| No line yet | "Nothing spent yet." |
| Lines that are level | "Everybody is level." |
| Lines that are not level | Each guest who is not level, worst first, and "2 payments to make". |
| While the read runs | "Loading…", never "nobody owes anything". |

The column appears on the calendar, rooms, guests, activities, money and trip
settings pages. It does not appear on the transport pages, the map, the run
sheet, or the analytics pages. It does not appear below 1280 pixels.

### Story 3.2: The analytics figures

Enter these lines: an expense of 90, an income of 20, and a transfer of 30.

| Card | Expected value |
|---|---|
| Spent | `€70.00`, which is 90 less 20. The transfer is left out. |
| Spent per person | `€70.00` divided by the headcount, so 4 people give `€17.50`. |
| Still owed | The sum of the positive balances. `€0.00` when the group is level. |

Click the "Spent" card and the "Still owed" card. Both open the money page.

## 4. The assistant

The assistant runs a model on the device. Load the model first, on Wi-Fi.

### Story 4.1: The assistant reads the accounts

Ask "who owes Marie?" and "how much did we spend?". The answer names the same
figures as the money page. Ask about a trip with no line. The assistant says
that there is no line, not that it has no access.

### Story 4.2: The assistant writes a line

Say "Marie paid 84 for the shopping, split between everyone". The assistant
adds one line. Make sure that these rules hold:

- A line with no day is filed under today.
- A line with no named guests is split between everybody.
- A payer who is not a guest of this trip is refused.
- A guest id from another trip is dropped, and never stored.
- An amount that does not add up under the amounts rule is refused.

Ask the assistant to edit a line and then to remove it. `updateExpense` never
creates a line.

### Story 4.3: The model download

Open the assistant page with no cached model. Each preset shows its size next to
its name, `748 MB`, `2.92 GB` and `4.59 GB`. A reader on mobile data is told to
find Wi-Fi first.

## 6. Transport, rooms and trip creation

### Story 6.1: A driver exports their runs

Open the transport page as a guest who drives a run that is still ahead. A
button under the departure banner exports the runs.

| Test | Expected output |
|---|---|
| Open the file in a calendar app | One event per run, from the leave time to the meeting time. |
| Read one event | An alarm rings 15 minutes before. |
| Export a second time | The entry moves. No copy is added. |
| A run that already met | It is not in the file. |
| A place name with a comma | The whole name is in the event. |

Turn the phone to flight mode and make sure that the calendar still rings.

### Story 6.2: The room cards

A room with every bed taken reads "Complete", in green, with a check icon. A
room with more people than beds reads "Over capacity", in red, with a warning
icon. No full room is red.

### Story 6.3: The timeline hint

Open the rooms page in the timeline view while one guest has no room. A line
reads "Drag a chip onto a room to give it a bed". Give every guest a room. The
line disappears. Open the page as a viewer. The line never appears.

### Story 6.4: The create form counts what you type

Type 6 guests, 3 rooms and 7 beds, and a pair of dates 7 nights apart. One line
reads "7 beds for 6 guests, 7 nights". Remove a bed. The line turns amber and
says how many beds are missing. A guest who stands for two people counts as two.

### Story 6.5: Room icons

Pick an icon for each room in the create form. Save the trip. Open the rooms
page. Each room keeps its icon.

### Story 6.6: A picked place saves itself

Pick a place in the location field. The map opens and the place is already
saved. Drag the pin. Each move saves. There is no Confirm button to press.

## 8. Cross-cutting checks

Run these against the money feature, because it is the new data path.

| Test | What to do | Expected output |
|---|---|---|
| Offline | Turn the network off. Add a line. | The line is saved. A toast says the app is offline. |
| Sync | Add a line on device A. | Device B shows the same line and the same balances. |
| Bad remote data | Have a peer write a line with no day, or no payer. | The line is dropped. The page still renders. |
| Huge remote amount | A peer writes an amount of 1e308. | No balance reads `NaN`. |
| Bad remote currency | A peer writes `€€€` as the currency. | The page falls back to euro. It never goes blank. |
| Delete a guest | Delete Bob while he has lines. | Bob's lines go. Bob leaves the shares of the other lines. No balance names him. |
| Delete the trip | Delete the whole trip. | No expense row of that trip is left in the database. |
| Timezone | Set the device to Tokyo, then to Los Angeles. | A line entered today is filed under today, in both. |
| Language | Switch to French. | Every money word is French. No key such as `money.expense.new` is on screen. |
| Keyboard | Reach the view switcher and move with the arrow keys. | The view changes and the focus follows. |
| Screen reader | Read the balances table. | The caption, the column headers and the guest names are announced. |
| Long list | Enter 200 lines. | The page stays usable, and the balances stay right. |
| Same-day trip | A trip that starts and ends on one day. | The night rule says there is no night to split. |
| No guest | A trip with no guest. | The form says so, and the payer list is empty and disabled. |

## 9. Automated cover

Three Playwright specs drive stories 1.1 to 1.8, 2.1, 2.2, 3.1, 3.2 and 5.1 in
a browser:

- `e2e/money-expenses.spec.ts` for the form, the list and the balances.
- `e2e/money-currency-and-stats.spec.ts` for the currency label, the analytics
  figures and the organiser's column.
- `e2e/money-navigation.spec.ts` for the bottom bar and the floating button.

Run them with:

```bash
bun run test:e2e e2e/money-expenses.spec.ts e2e/money-currency-and-stats.spec.ts e2e/money-navigation.spec.ts
```

The arithmetic behind the stories is pinned by unit tests in
`src/features/money/lib/__tests__/`. The assistant stories are not automated,
because they need a model on the device.

## 10. What this QA pass already found and fixed

Four defects came out of writing the tests above. All four are fixed in the
same change as this document.

| Defect | What went wrong | The fix |
|---|---|---|
| The organiser's column was mounted on every phone | A CSS class hid it below 1280 pixels, but the component still mounted, ran its live database read on every trip page, and put a second invisible copy of every guest and room name in the document. | `Layout` now asks the viewport before it mounts the column. |
| The calendar hand-off to the travel form was dead | "New arrival" sends the reader to `/trips/<id>/transports?new=1`. The page stopped reading that flag after a merge, so the reader landed on the empty list the hand-off exists to skip. | The flag is read again on the first render, and dropped from the address afterwards. |
| The end-to-end suite was red | The day's work broke 37 results across 8 spec files. Nobody had run the suite. | The specs now name the page's own list instead of the whole document. |
| A stale comment in `Layout` | It named the old bottom bar, without the accounts. | Rewritten to match the code. |

The suite is green again: 449 results across the local projects.
